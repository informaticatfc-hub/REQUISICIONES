### 1.1 KPI: No existe selector de obra única directa

**Descripción del problema:**  
El selector de obras en `pages/reportes_kpi.php` muestra checkboxes con botones "Todas" y "Ninguna". Para activar el modo drilldown (Obra → Presiones → Hojas), el usuario necesita marcar exactamente 1 checkbox. El sistema NO ofrece un control explícito de "ver solo esta obra" desde el panel de filtros.

El `obraUnicaSeleccionada` en `assets/js/reportes_kpi.js` (línea 47) ya detecta cuando hay 1 obra marcada y activa el drilldown automáticamente. El gap es solo de UX: el director no sabe que debe dejar exactamente 1 marcada.

**Causa raíz:** Falta un control directo de selección única (dropdown o lista de radio buttons).

**Solución propuesta — Dropdown de selección rápida encima del selector actual:**

En `pages/reportes_kpi.php`, dentro del bloque del selector de obras (después del `<label class="form-label">Obras</label>`), agregar:

```html
<!-- Modo obra única: selector rápido -->
<select class="form-select form-select-sm mb-2"
        x-model="obraRapidaId"
        x-on:change="seleccionarObraRapida($event.target.value)">
    <option value="">— Todas las obras (multi-selección) —</option>
    <template x-for="obra in obras" :key="obra.obras_id">
        <option :value="String(obra.obras_id)"
                x-text="obra.obras_nombre"></option>
    </template>
</select>
<hr class="my-1">
```

Y en `assets/js/reportes_kpi.js`, dentro de `data:` agregar `obraRapidaId: ''`, y en `methods:` agregar:

```js
seleccionarObraRapida: function(val) {
    this.obraRapidaId = val;
    if (!val) {
        this.filtros.obraIds = this.obras.map(function(o){ return String(o.obras_id); });
    } else {
        this.filtros.obraIds = [val];
    }
},
```

También sincronizar el dropdown cuando se use el drilldown desde el gráfico (en `drillDown`):

```js
drillDown: function(obraId) {
    this.filtros.obraIds = [String(obraId)];
    this.obraRapidaId   = String(obraId);   // <-- agregar esta línea
    // ...resto del código existente
},
verTodas: function() {
    this.filtros.obraIds = [];
    this.obraRapidaId   = '';              // <-- agregar esta línea
    // ...resto del código existente
},
```

**Por qué mejora la trazabilidad:**  
El director trabaja obra por obra en sus revisiones. Un clic directo vs. navegar checkboxes reduce el tiempo de análisis y evita errores de selección múltiple accidental.

### 1.2 all_presiones: Sin importación de CFDI XML (facturas SAT)

**Descripción del problema:**  
El módulo `pages/all_presiones.php` permite exportar/importar XLSX y CSV para actualizar "Pago Autorizado" y "Observaciones", pero **no tiene soporte para importar XMLs de CFDI** (Comprobante Fiscal Digital por Internet del SAT).

En el contexto de una constructora mexicana, cada factura de proveedor tiene su XML del SAT con datos estructurados que actualmente deben capturarse a mano en el sistema.

**Dato de la BD actual:** La tabla `hojasrequisicion` no tiene ningún campo para UUID fiscal, ni RFC del emisor del CFDI. Esto significa que hoy no hay trazabilidad fiscal entre el sistema y los comprobantes del SAT.

**Solución — Dos partes:**

#### Parte A: Migración de BD

```sql
-- Migración: 2026_06_22_012_cfdi_fields.sql
ALTER TABLE `hojasrequisicion`
    ADD COLUMN `hojaRequisicion_cfdiUUID`      char(36)      DEFAULT NULL 
        COMMENT 'UUID del timbrado (SAT) — identificador fiscal único',
    ADD COLUMN `hojaRequisicion_cfdiRfcEmisor` varchar(13)   DEFAULT NULL 
        COMMENT 'RFC del emisor (proveedor) en el CFDI para validación cruzada',
    ADD COLUMN `hojaRequisicion_cfdiFecha`     datetime      DEFAULT NULL 
        COMMENT 'Fecha de emisión del CFDI',
    ADD COLUMN `hojaRequisicion_cfdiTotal`     decimal(12,2) DEFAULT NULL 
        COMMENT 'Total del CFDI — comparar vs hojaRequisicion_total para detectar diferencias';

-- Índice para búsqueda por UUID
ALTER TABLE `hojasrequisicion`
    ADD UNIQUE KEY `uk_cfdi_uuid` (`hojaRequisicion_cfdiUUID`);
```

#### Parte B: Botón de importación XML en all_presiones

En `pages/all_presiones.php`, dentro de `excel-utility-bar` de cada obra, agregar:

```html
<button class="btn btn-outline-info btn-sm" type="button"
        x-on:click="triggerImportXML(index)"
        x-show="canPresionesWrite"
        title="Importar CFDI XML del SAT">
    <i class="bi bi-file-code"></i> Importar XML CFDI
</button>
<input type="file" x-bind:id="'xmlImport'+index"
       accept=".xml" class="d-none"
       x-on:change="importarCFDI($event, index)">
```

En `assets/js/all_presiones.js`, función de importación:

```js
triggerImportXML: function(index) {
    document.getElementById('xmlImport' + index).click();
},

importarCFDI: function(event, indexObra) {
    const file = event.target.files[0];
    if (!file) return;
    event.target.value = '';

    const reader = new FileReader();
    reader.onload = (e) => {
        const parser = new DOMParser();
        const xml    = parser.parseFromString(e.target.result, 'application/xml');

        // Soporte CFDI 3.3 y 4.0
        const ns = 'http://www.sat.gob.mx/cfd/4';
        const ns33 = 'http://www.sat.gob.mx/cfd/3';
        const comp = xml.querySelector('Comprobante') || xml.getElementsByTagNameNS(ns, 'Comprobante')[0]
                       || xml.getElementsByTagNameNS(ns33, 'Comprobante')[0];

        if (!comp) {
            Swal.fire('Error', 'El archivo no es un CFDI válido', 'error');
            return;
        }

        const tfd    = xml.querySelector('TimbreFiscalDigital');
        const emisor = xml.querySelector('Emisor');

        const cfdiData = {
            uuid    : tfd?.getAttribute('UUID')          || '',
            rfc     : emisor?.getAttribute('Rfc')        || '',
            nombre  : emisor?.getAttribute('Nombre')     || '',
            total   : parseFloat(comp.getAttribute('Total') || 0),
            fecha   : comp.getAttribute('Fecha')         || '',
            moneda  : comp.getAttribute('Moneda')        || 'MXN',
        };

        this.sugerirMatchCFDI(indexObra, cfdiData);
    };
    reader.readAsText(file, 'UTF-8');
},

sugerirMatchCFDI: function(indexObra, cfdiData) {
    const obra = this.presiones[indexObra];
    if (!obra) return;

    // Buscar fila cuyo total coincida ±1% con el del CFDI
    const match = (obra.Presion_Obra || []).find(row => {
        return Math.abs(parseFloat(row.total) - cfdiData.total) / (cfdiData.total || 1) < 0.01;
    });

    const msg = match
        ? `CFDI de ${cfdiData.nombre} (RFC: ${cfdiData.rfc})\n` +
          `Total: $${cfdiData.total.toLocaleString('es-MX')}\n` +
          `Posible coincidencia: ${match.NumReq} - ${match.proveedor}\n\n` +
          `¿Asignar UUID ${cfdiData.uuid} a esta hoja?`
        : `CFDI de ${cfdiData.nombre} (RFC: ${cfdiData.rfc})\n` +
          `Total: $${cfdiData.total.toLocaleString('es-MX')}\n` +
          `UUID: ${cfdiData.uuid}\n\n` +
          `No se encontró coincidencia automática. ¿Registrar de todas formas?`;

    Swal.fire({
        title  : 'CFDI detectado',
        text   : msg,
        icon   : match ? 'success' : 'warning',
        showCancelButton: true,
        confirmButtonText: 'Asignar',
        cancelButtonText : 'Cancelar',
    }).then(result => {
        if (result.isConfirmed && match) {
            match._cfdiUUID  = cfdiData.uuid;
            match._cfdiRfc   = cfdiData.rfc;
            match._cfdiFecha = cfdiData.fecha;
            match._cfdiTotal = cfdiData.total;
            match._dirty = true;
            Swal.fire('Asignado', 'El UUID del CFDI fue asociado a la hoja. Guarda los cambios para confirmar.', 'success');
        }
    });
},
```

**Por qué mejora la trazabilidad:**  
Tener el UUID del SAT en cada hoja convierte el sistema en un registro fiscal auditable. En una revisión del SAT o auditoría interna, el cruce UUID ↔ hoja de requisición es inmediato y sin ambigüedad.

### 1.3 Marca de agua al frente en el PDF exportado

**Descripción del problema:**  
En `assets/js/pdfGenerate.js`, líneas 60-61:

```js
doc.addImage(watermark, 'JPG', 0, 0, 297, 210);  // ← capa 1: watermark ENCIMA de la tabla
doc.addImage(image,     'PNG', 10, 10, 25, 25);  // ← capa 2: logo
```

jsPDF dibuja en orden secuencial. La tabla ya fue dibujada antes (por `autoTable`), pero el watermark se añade como capa por encima del contenido existente, no por debajo. Resultado: la imagen tapa el texto.

El intento correcto habría sido dibujar el watermark ANTES de llamar a `autoTable`, pero eso requeriría refactorizar el orden de generación completo.

**Soluciones disponibles (de menor a mayor esfuerzo):**

| Opción | Descripción | Esfuerzo |
|---|---|---|
| **A — Eliminar watermark** | Quitar línea 60. PDF queda limpio con solo el logo | 5 min |
| **B — Watermark antes de la tabla** | Mover `addImage(watermark)` al inicio, antes de `autoTable`, con `setGState` para 20% de opacidad | 2 horas |
| **C — PDF server-side** | Generar con dompdf/PHP donde el control de capas es real | 8+ horas |

**Recomendación: Opción A (eliminar).** Un PDF limpio y legible es más valioso que uno con marca de agua que obstruye los datos financieros. La identidad corporativa ya la da el logo pequeño en la esquina.

**Cambio concreto en `pdfGenerate.js`:**

```js
// Línea 60 — ELIMINAR esta línea:
doc.addImage(watermark, 'JPG', 0, 0, 297, 210);

// Línea 61 — CONSERVAR (logo corporativo):
doc.addImage(image, 'PNG', 10, 10, 25, 25);
```

Y en la línea 4 eliminar también la variable que ya no se usa:
```js
// Línea 4 — ELIMINAR:
var watermark = IMAGE_WATERMARK_BASE64;
```

Esto también reduce el tamaño del archivo JS en ~750 KB (el base64 del watermark está incrustado).

La inconsistencia de nombre (`hoja` vs `hoja**s**`) sugiere que fueron creadas en momentos distintos sin coordinación. Esto genera:

- Datos duplicados o contradictorios si se llenan ambos

### 3.2 Campos faltantes en `presiones` para trazabilidad temporal

La tabla `presiones` solo tiene `presiones_fechaCreacion`. Sin las fechas de transición de estado, es imposible calcular tiempos de ciclo del proceso.

```sql
-- Migración: 2026_06_22_013_presiones_fechas_estado.sql
ALTER TABLE `presiones`
    ADD COLUMN `presiones_fechaEnviado`    datetime DEFAULT NULL
        COMMENT 'Cuándo se mandó a revisión/dirección',
    ADD COLUMN `presiones_fechaAutorizado` datetime DEFAULT NULL  
        COMMENT 'Cuándo fue autorizada o rechazada por dirección';
```

Con estos campos, el KPI de "tiempo promedio de autorización" se puede calcular directamente en SQL:

```sql
SELECT 
    AVG(DATEDIFF(presiones_fechaAutorizado, presiones_fechaCreacion)) AS dias_promedio_autorizacion,
    obras.obras_nombre
FROM presiones
JOIN obras ON obras.obras_id = presiones.presiones_obra
WHERE presiones_estatus IN ('AUTORIZADO', 'RECHAZADO')
  AND presiones_fechaAutorizado IS NOT NULL
GROUP BY obras.obras_id;
```

### 3.3 Tabla `obras` sin campos de gestión de proyecto

La tabla tiene nombre, clave, tipo, estatus y ciudad, pero no tiene:

```sql
ALTER TABLE `obras`
    ADD COLUMN `obras_fecha_inicio`  date          DEFAULT NULL,
    ADD COLUMN `obras_fecha_fin`     date          DEFAULT NULL,
    ADD COLUMN `obras_presupuesto`   decimal(14,2) DEFAULT NULL
        COMMENT 'Presupuesto aprobado total para comparar vs gasto ejecutado en KPI';
```

`obras_presupuesto` es el campo más crítico: sin él, el KPI de dirección no puede mostrar "% del presupuesto ejecutado" que es el indicador #1 en proyectos de construcción.
